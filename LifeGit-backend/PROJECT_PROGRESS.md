# LifeGit 后端开发进度报告

## 项目概述

**LifeGit** 是一个物品/地点全生命周期管理系统，核心理念是为每个实体（物品或地点）建立完整的"生命档案"，记录从购入到转让的每一个重要时刻。

**技术栈：** Python Flask + MySQL + JWT认证

**后端地址：** `http://localhost:5000`

### 模块三：Commit 结构化事件系统 ✅（7种事件类型）

这是产品的核心功能，每个事件都是结构化记录，不是随意评论。

**事件类型一览：**

| 事件类型 | 标识 | 核心字段 | 状态 |
|---------|------|---------|------|
| 购入 | `purchase` | 时间、价格、渠道、开箱图文、初始体验 | ✅ |
| 维护保养 | `maintenance` | 时间、项目、费用、维修点、零件照片、维修凭证、质保信息 | ✅ |
| 升级改装 | `upgrade` | 时间、项目、费用、升级前后规格、性能提升感受 | ✅ |
| 使用体验 | `experience` | 时间、评分、场景、优缺点标签、详细描述 | ✅ |
| 体验节点 | `memory` | 时间、标题、类型、参与人、地点、情感评分、故事背景、情感体验、收获感悟 | ✅ |
| 故障维修 | `fault` | 时间、描述、发生频率、故障类型、是否已维修、维修详情、官方回应、处理满意度 | ✅ |
| 转让出售 | `transfer` | 时间、价格、原因、物品状态、对下一个主人的寄语、使用建议 | ✅ |

**事件API：**

| 功能 | 接口 | 状态 |
|------|------|------|
| 获取所有事件类型 | `GET /api/event/types` | ✅ |
| 获取事件表单结构 | `GET /api/event/schema/<type>` | ✅ |
| 创建事件 | `POST /api/event/create` | ✅ |
| 事件列表（分页+筛选） | `GET /api/event/list/<repo_id>` | ✅ |
| 事件详情 | `GET /api/event/<id>` | ✅ |
| 删除事件 | `DELETE /api/event/<id>` | ✅ |

**设计亮点：**
- 每种事件有独立的 JSON Schema 定义，前端可动态渲染表单
- 后端自动验证必填字段、数据类型、范围、长度
- `content` 字段使用 MySQL JSON 类型，灵活存储不同结构

### 模块四：负面信息确认机制 ✅

对数据严谨性的尊重，提交负面信息时弹出确认框：

- **故障维修事件** → "此记录将公开，可能帮助他人避坑，是否确认提交？"
- **低评分体验（≤2星）** → "此负面体验记录将公开，是否确认提交？"
- **转让出售** → "此记录将标记物品已转让，完成生命周期闭环，是否确认？"
- **报废** → "此记录将标记物品已报废，是否确认？"

| 功能 | 接口 | 状态 |
|------|------|------|
| 检查是否需要确认 | `POST /api/event/check_confirmation` | ✅ |

流程：前端先调用检查接口 → 若需确认则弹窗 → 用户确认后携带 `skip_confirmation: true` 重新提交

### 模块五：Issue 信任问答系统 ✅

围绕实体构建知识库与社区。

| 功能 | 接口 | 状态 |
|------|------|------|
| 创建Issue | `POST /api/issue/create` | ✅ |
| Issue列表（分页+状态筛选） | `GET /api/issue/list/<repo_id>` | ✅ |
| Issue详情+回复列表 | `GET /api/issue/<id>` | ✅ |
| 更新Issue状态 | `PUT /api/issue/<id>/status` | ✅ |
| 删除Issue | `DELETE /api/issue/<id>` | ✅ |
| 创建回复（支持@提醒） | `POST /api/reply/create` | ✅ |
| 设置最佳答案 | `PUT /api/reply/<id>/best` | ✅ |
| 取消最佳答案 | `PUT /api/reply/<id>/cancel_best` | ✅ |

**三大核心机制：**

1. **状态管理：** open → answered → closed（首次回复自动变为answered）

2. **最佳答案：** 仓库所有者或提问者可以将某个回复设为"最佳答案"，置顶显示，同一Issue只允许一个

3. **@提醒功能：** 回复中可@其他用户，被@用户收到未读通知

## 数据库设计（6张表）

```
user      → 用户表（认证、个人信息）
  ↓
repo      → 仓库表（物品/地点实体）
  ↓
event     → 事件表（结构化生命周期记录）
  ↓
issue     → 问题表（信任问答）
  ↓
reply     → 回复表（含最佳答案机制）
  ↓
mention   → @提醒表（未读/已读状态）
```

**核心设计：**
- `event` 表的 `event_type` 为枚举字段，`content` 为 JSON 字段
- 不同事件类型存储不同的结构化数据，扩展性强
- 新增事件类型无需修改表结构
